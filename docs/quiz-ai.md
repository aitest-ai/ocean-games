# 🤖 用 AI 把教材轉成題目：格式、提示詞範本與接口說明

> 給老師與學校資訊人員。**這個版本沒有串接任何 AI 服務**，網站不會把教材送到任何地方。
> 目前的做法是：編輯器幫老師產生「提示詞」→ 老師貼到**自己選用的 AI 工具** → 把回覆貼回編輯器檢查。
> 之後若學校有自己的 AI 服務（或後端），可以照第四節的接口接上。

## 一、老師怎麼用（現在就能用）

1. 打開「✏️ 題庫編輯器」→ 開啟（或新增）一份「我的題庫」→ 分頁「🤖 用 AI 轉題」。
2. 貼上教材文字（一段課文、講義），填科目、年級、題數，勾題型（選擇、是非、排序、配對、數字）。
3. 按「產生提示詞」→「📋 複製提示詞」，貼到您的 AI 工具。
4. 把 AI 回覆的**整段文字**貼回第二個框，按「檢查並加入題庫」。
   - AI 常會在 JSON 前後加說明文字、或用 ``` 包起來，編輯器會自己找出 JSON。
   - 格式不對的題目會用白話列出（第幾題、哪裡錯），**不會**加入題庫；正確的題目直接加入。
5. **到「📋 題目」逐題檢查**：AI 可能出錯、答案可能不對、錯誤選項可能也對。這一步不能省。

### 注意事項

- **版權**：貼給 AI 的教材要有使用權；AI 產生的題目也請確認沒有整段照抄受版權保護的內容。
- **隱私**：不要貼學生姓名、座號對照、成績或任何個人資料。提示詞本身只要求「出題」，不含任何學生資料。
- **選哪個 AI 工具**由學校決定（要注意該工具的資料使用條款、是否允許未成年人使用、是否會拿輸入的內容去訓練）。

## 二、提示詞範本

編輯器產生的就是這個範本（`src/quiz/ai.js` 的 `buildPrompt`），老師也可以直接複製修改：

```
你是國小老師的出題助手。請根據下面的「教材」出 10 題給四年級學生的自然題目，用繁體中文（臺灣用語）。

【規則】
1. 只根據教材內容出題，不要加入教材以外的知識；不確定的不要出。
2. 每題要短（題目最好 40 字以內，選項 12 字以內），學生要站在 2 公尺外看投影幕作答。
3. 題型只用下面這些：
- 選擇題 choice：2～4 個選項（options），answer 寫正確選項的字母 A～D
- 是非題 tf：一句話，answer 寫 "○"（對）或 "×"（錯）
4. 每題加：difficulty（1 簡單、2 普通、3 困難，三種都要有）、explain（一句話解說，答錯時給學生看）、tags（1～2 個主題標籤）。
5. 錯誤選項要「看起來合理」，但只能有一個正確答案；不要出「以上皆是／以上皆非」。
6. 不要使用任何人的真實姓名、照片或個人資料；不要抄錄受版權保護的長段文字。

【輸出格式】只輸出一個 JSON，不要其他文字：
{ "format": "taikan-quiz", "version": 1, "title": "…", "questions": [ … ] }

【教材】
（貼上教材）
```

**為什麼這樣寫**：

- 「只根據教材」→ 降低 AI 自己編造知識的機會。
- 「題目 40 字、選項 12 字以內」→ 投影時字夠大，跑道門、選項卡放得下。
- 「只能有一個正確答案、不要以上皆是」→ 身體作答一次只能選一個。
- 指定 JSON 格式 → 可以直接匯入；格式細節見下一節和 `data/quiz/schema.json`。

### 其他好用的提示詞（老師可以自己加在範本後面）

- 「請多出排序題，例如事件的先後順序、步驟。」（歷史、自然實驗步驟）
- 「請出配對題：生字和注音／英文和中文。」
- 「請把題目改得更簡單，適合二年級。」
- 「請把錯誤選項設計成學生最常見的錯誤觀念。」（概念診斷）

## 三、題庫格式（給 AI 與資訊人員）

- 完整格式說明：`docs/quiz.md` 第三節。
- 嚴格的 JSON Schema：`data/quiz/schema.json`（可以交給支援「結構化輸出」的 AI 工具）。
- 6 種題型：`choice`、`tf`、`order`、`match`、`image`、`number`；最少要有 `type`、`q` 與該題型需要的欄位。
- 遊戲讀檔比 Schema 寬鬆：答案也可以寫選項文字或從 1 開始的數字，題型也可以寫中文（選擇、是非…），讓 AI 偶爾不守規則時也讀得進來；讀不進來的會給白話錯誤訊息。

## 四、接口（之後要串接自己的 AI 服務時）

程式：`src/quiz/ai.js`

| 函式 | 做什麼 |
|---|---|
| `buildPrompt({ material, subject, grade, count, types, difficulty })` | 產生上面的提示詞文字 |
| `extractJSON(text)` | 從 AI 回覆中找出 JSON（處理 ``` 包裝與前後說明文字） |
| `parseAIOutput(text, images)` | 找出 JSON 並用一般題庫的規則檢查，回傳 `{ bank, errors, warnings }` |
| `generateWithAI(options, config)` | **預留**：送出提示詞到學校自己的服務 |

`generateWithAI` 只有在頁面載入前設定了 `window.QUIZ_AI` 才會動作，否則直接回報「尚未設定 AI 服務」，**不會送出任何資料**：

```html
<script>
  // 只有學校自己的服務才這樣設定；網址與金鑰請由後端代管，不要把 AI 公司的金鑰寫在網頁裡
  window.QUIZ_AI = { endpoint: 'https://（學校的伺服器）/quiz-ai', headers: { } };
</script>
```

服務端的約定：

```
POST {endpoint}
Content-Type: application/json
{ "prompt": "（buildPrompt 產生的文字）" }

→ 200 OK
{ "text": "（AI 的回覆，裡面要有 taikan-quiz JSON）" }
```

**建議的後端做法**（給資訊人員）：

1. 金鑰放在後端，不要放在網頁或 GitHub。
2. 後端只轉送 `prompt`，不要記錄教材內容；若要記錄，請先確認學校的個資與著作權規範。
3. 回傳前可以先用 `data/quiz/schema.json` 驗證；不合格時再請 AI 重試一次。
4. 限制每位老師每天的次數，避免費用失控。
5. 編輯器目前沒有「一鍵產生」按鈕（因為沒有串接）；接好服務後，只要在 `mountAIPanel` 加一個按鈕呼叫 `generateWithAI`，結果交給同一套「檢查並加入」流程即可。

## 五、我的建議與風險

- **建議**：把 AI 當「出題草稿」，老師審核後才用；最有價值的是請 AI「把錯誤選項設計成常見錯誤觀念」，遊戲結算時的答錯清單就能變成很好的補救教學材料。
- **風險**：AI 可能產生錯誤答案或不適合的內容；學生是未成年人，**不要**讓學生自己直接用 AI 產生題目。
- **授權**：AI 產生的內容在不同服務條款下的權利歸屬不同，商用前請法律專業確認。
