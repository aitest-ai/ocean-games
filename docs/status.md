## 打擊練習：揮棒延遲改善（接在 #7 揮棒測試、#8 側身站之後）

**問題**：鏡頭模式下，玩家已經揮完棒，畫面上的「揮棒」提示和人物要過好一陣子才出現。

**量到的原因**（工具在 `tools/latency/`；用 three.js 人偶的揮棒影像交給 MediaPipe 算骨架，記下真實的「開始往前揮」時間）：

1. **辨識太晚**（最大的原因）：原本要等雙手揮到擊球點附近才送出「揮棒」，正面站是開始揮之後 230～317 毫秒；**側身站時手是斜斜往前下方揮，根本抓不到**，只在收棒時誤觸發（約 1 秒後）。
2. **人物還會等球**：提早揮時，人物會停在原地，等球到本壘才揮（最多再晚約 0.2 秒）。
3. **推論多做一倍的工**：MediaPipe 設成「找 2 個人」，只有一個人時每格都要多跑一次找人模型（雲端實測 55 → 101 毫秒）。
4. 事件要等下一格畫面才畫出來（+17～33 毫秒）；時間戳不是拍攝時間。

**改了什麼**：

- 新增「揮棒起動」訊號：雙手一開始往前揮就送出，人物馬上從「往前揮」開始動、不再停住等球；判定仍用原本的擊球事件。如果其實沒有揮（只是手動了一下），人物會「止揮」收回。
- 側身站的揮棒抓得到了；收棒不會被當成再揮一次。
- 打擊練習只找 1 個人（推論約快一倍；代價是這款不會提醒「鏡頭前有兩個人」）。
- 用瀏覽器提供的「這一格拍到的時間」當時間戳，新影格一到就算，事件在同一格就畫出來。
- 選單新增「顯示延遲診斷」（或網址加 `?diag=1`）：畫面左邊會顯示「起動 → 人物揮棒」幾毫秒，以及辨識、鏡頭與推論、畫面各佔多少。

**結果**（從雙手開始往前揮，到人物開始揮）：

| 段落 | 原本 | 現在 | 怎麼量的 |
|---|---|---|---|
| 辨識 | 正面 230～317 ms；側身抓不到 | 97～250 ms（側身 97～150） | 人偶影像經 MediaPipe，30 格/秒，自動測試 |
| 鏡頭＋推論 | 平板未知；找 2 人推論約兩倍 | 平板未知（雲端沒有顯示卡）；找 1 人 | 請看平板上的延遲診斷 |
| 事件 → 畫面 | 0～33 ms＋等球最多約 200 ms | 同一格（0～3 ms） | 雲端假鏡頭實測 |

**目標 150 毫秒：做不到，誠實說明**。光是「看得出手開始往前揮」就要 3～5 格影格（30 格/秒＝每格 33 毫秒），再加上鏡頭與推論。預估平板上是 **約 170～330 毫秒**（原本約 450～700 毫秒）。請用延遲診斷量實際的數字。

**需要您用平板確認**：見 PR 說明的「只能真機驗證」清單。

## 第三輪：陸地系列開張——棒球場與打擊練習

### 一、這一輪做了什麼

1. **棒球場場地底座**（可以給之後的遊戲重用）
   - 照**少棒 60 呎規格**做的 3D 球場：壘間 18.29 公尺、投手板到本壘 14.02 公尺、全壘打牆左右 61 公尺／中外野 65.5 公尺。採用的每個數字和出處列在〈[體感野球企劃](baseball-plan.md)〉第 1 節。
   - 有：內外野草地（割草紋）、紅土、壘包、投手丘（真的隆起 15 公分）、本壘板、白線與打擊區、外野牆與黃色界外標竿、後擋網、兩側球員休息區、本壘後方有屋頂的看台與一三壘看台（坐滿觀眾）、外野草坡、記分板（會顯示打擊結果）、6 座燈塔、天空、星星、遠山與樹林。
   - **三個時段**：白天、黃昏、夜間（夜間燈塔會發光，內野最亮）。
   - **全部用程式生成**，沒有用任何外部圖片、模型或錄音，所以沒有授權問題。3D 程式庫是 three.js（MIT 授權），放在我們自己的網站。
   - **畫質分級**：平板自動選「低」（關陰影、貼圖小一半、觀眾少一點）。
   - 另外做了一個「**棒球場展示**」頁：不用鏡頭，可以切時段、視角（本壘後方、打者、投手丘、空拍、看台、外野）和畫質，畫面上也列出場地尺寸。
2. **⚾ 打擊練習**（第一款可玩原型）
   - 投手投球 → 學生**空手**做雙手揮棒 → 判定**安打／界外／揮空**（另外還有全壘打、長打、出局，以及「壞球沒揮：選得好」）。
   - 太早揮會打到三壘側、太晚到一壘側；打出去的球照真實物理飛（重力、空氣阻力、彈跳、撞牆）。
   - 畫面：捕手後上方的打擊視角、好球框、球快到時會縮小變綠的「時機圈」、左上角「太早 ← 剛好 → 太晚」條、打出去會切轉播鏡頭追球、全壘打時觀眾跳起來。
   - 三種難度（簡單、普通、挑戰），一輪 10 球（挑戰 12 球），約 1.5～2 分鐘。
   - 可以用**鍵盤**（空白鍵或 K 揮棒）、**畫面上的大按鈕**（平板沒有鏡頭時），或**鏡頭**玩。
3. **輸入層新增「雙手揮棒」事件 `bat`**：原本的「揮臂」是單手的，揮棒時兩隻手會各算一次，而且要揮到快結束才觸發，抓時機會慢。新事件只算一次、揮到一半就送出，還會說揮棒高度（高／中／低），之後體感野球可以用。已寫進〈輸入層說明〉。海洋系列不會收到這個事件，帆船的「揮手換舷」不受影響。
4. **首頁新增「陸地系列」**：打擊練習、棒球場展示、體感野球企劃三張卡片，以及給學生看的「陸地系列怎麼玩」動畫卡片與棒球安全提醒。風格跟海洋系列一樣。
5. **〈[體感野球企劃](baseball-plan.md)〉**：完整體感野球的建議玩法、分階段開發順序、場地規格出處、畫面風格、畫質取捨、我的建議與風險。

### 二、我替您做的決定與理由

| 決定 | 理由 |
|---|---|
| 場地用**少棒 60 呎**規格（壘間 18.29 m、投捕 14.02 m、外野 200 呎） | 國小高年級在台灣打的就是這個規格（台灣世界少棒聯盟國小組、Little League Majors）。距離感跟學生去少棒場看到的一樣，科技課也能拿來算。 |
| 中外野 215 呎、牆高 1.8 m、界外區 7.5 m、內野紅土半徑 50 呎 | 規則沒有規定或資料互相矛盾（紅土弧有 50 呎和 65 呎兩種說法），我選看起來最像台灣少棒場的數字，文件裡都標「自訂」。 |
| 3D 改用 **three.js**，不沿用海洋系列的海面引擎 | 海面引擎是專門畫海的；球場需要看台、人、燈光、陰影，用 three.js 做得快、平板也跑得動。同一套遊戲外殼兩種世界都能用，海洋遊戲完全不受影響（已重測）。 |
| 風格：**寫實比例、乾淨的轉播風**，人物用簡單幾何形狀 | 尺寸和光線寫實，人物和觀眾簡化：平板跑得動，而且全部同一種質感。不模仿實況野球的角色（那是 Konami 的著作），只參考打擊視角、時機提示這類玩法感覺。 |
| **全部程式生成、不用外部素材** | 沒有授權疑慮、檔案小、風格一致。three.js 本身是 MIT。所以頁尾列的是 three.js、MediaPipe 和「本專案程式生成」；**沒有 CC0／CC-BY 素材需要標作者**。 |
| 新增輸入事件 `bat`，而不是只用 `swing` | 單手揮臂事件遇到雙手揮棒會算兩次、觸發太晚。打擊最重要的就是時機，所以值得新增。 |
| 球速比真實少棒**慢很多**（簡單 45 公里/小時） | 鏡頭判斷有延遲，學生也需要時間看球。真實少棒約 80～100 公里/小時，體感遊戲做不到也不安全。 |
| **自動校正揮棒時機**（預設開） | 每台平板、每位學生的延遲不一樣。遊戲依前幾球「偏早或偏晚」慢慢修正（最多 0.12 秒），老師不用手動調。 |
| 揮棒的替代方式：**單手揮（預設開）、身體傾斜、自動揮棒** | 符合企劃書「每個動作都能跳過」。自動揮棒時學生改成練習看好壞球。 |
| 棒球專屬安全規範：**空手揮、周圍 1.5 公尺、左右不站人、安全員站正後方** | 揮棒會甩到身體兩側，比海洋系列（半徑 1 公尺）需要更大空間。首頁、選單、怎麼玩畫面都有寫。 |
| 打擊視角放在捕手後上方，捕手與主審放低 | 學生要看得到好球框和球；這也是電視轉播和棒球遊戲最常見的打擊視角。 |
| 球畫得比真實大 30%、地上有球的影子 | 平板螢幕小，真實大小的球不好看清楚；影子能幫學生判斷球的高低。 |

### 四、雲端沒辦法驗證、需要您用平板實測的

1. **真人雙手揮棒**（最重要）：請打開「輸入層測試頁」→「📷 鏡頭」，坐著、站著各揮 10 次，看「揮棒（往左）」有沒有每次都出現。也請試試整理頭髮、伸懶腰、拍手，看會不會被誤認成揮棒。可以按「⏺ 錄製骨架 10 秒」把骨架檔給我（只有座標數字）。
2. **揮棒時機準不準**：用鏡頭玩打擊練習簡單模式，學生覺得「剛好」時，左上角是不是也顯示「剛好」？第一、二球可能偏，之後自動校正會修正；請看結算畫面寫的「自動校正了幾毫秒」，超過 100 毫秒請告訴我。
3. **平板順暢度**：鏡頭模式下右下角的「格/秒」，25 以上算順。夜間、黃昏也各試一次。
4. **黃昏、夜間在平板上會不會太暗**：教室開燈時看得清楚嗎？
5. **安全空間**：周圍 1.5 公尺、左右不站人，在您的教室排得出來嗎？學生會不會不自覺往前踏步？
6. **替代方式**：「單手揮」「身體傾斜」「自動揮棒」，請特教老師一起看是否足夠。
7. **難度與時間**：一輪 10 球約 1.5 分鐘是否剛好；五年級學生的星星數。
8. **學校網路**：第一次打開打擊練習會多下載約 0.7 MB 的 three.js，請確認不會被擋（首頁的網路測試只測姿態模型）。
9. **畫面按鈕**：沒有鏡頭時，平板右下角的「⚾ 揮棒」大按鈕，點起來反應夠不夠快（從點下去到揮棒約 0.37 秒，判定時已扣掉）。

## 第二輪：衝浪、帆船、首頁整合、模型自架

### 一、這一輪做了什麼

1. **兩款新遊戲（可玩）**
   - 🏄 **衝浪**：身體傾斜轉彎、蹲低（坐著就身體往前彎）加速、舉單手擺花式姿勢。閃開漂流木和礁石，**撿起海上垃圾**（寶特瓶、浮球）。撞到落水 2 秒後自動站回板上，分數不歸零。一場 90 秒。
   - ⛵ **帆船**：傾斜轉舵、揮手換舷、舉左手拉緊帆／舉右手放鬆帆、陣風時蹲低壓船。帆變**綠色**＝吃到風、**灰色**＝沒吃到風；左上角風向圖的紅色扇形是「開不動區」，逆風要走之字形。依序繞過黃色標誌後穿過終點門。
   - 兩款都有三級難度（＝三種天氣）、「坐著玩」開關、每個動作都能在選單關掉並由遊戲自動代替，也都遵守安全規範（看不到人自動暫停、雷電關閉、跳躍預設關閉）。
2. **三款共用同一個遊戲外殼**：選單、怎麼玩、暫停、結算、鏡頭跟隨、畫質分級都一樣，學生學會一款，其他兩款的操作方式就一樣。
3. **首頁整合**：首頁一進來就是「選一款遊戲」，三張卡片各有一個會動的小人示範主要動作，並標出強度、可坐著玩、一場多久。
4. **給學生看的「怎麼玩」畫面**：每次打開遊戲會先出現。每個動作一張卡片，小人會一直重複示範（小人就是鍵盤模擬用的那個模擬人偶，所以示範的動作就是鏡頭要看的動作），旁邊寫「做這個 → 遊戲裡會怎樣」，並標出「🪑 坐著怎麼做」「⏭️ 做不到可以關掉」。學生**雙手舉高 1 秒**就能關掉說明，不需要碰平板。被關掉的動作不會出現在說明裡。
5. **姿態模型改放在我們自己的網站**（詳見第三節）。首頁另外加了「📶 測試學校網路」按鈕。
6. **依企劃書的共同原則補強三款遊戲**：
   - 暫停後繼續會先倒數 3、2、1。
   - 新增「減少晃動」選項：鏡頭不跟著浪起伏，給容易暈的同學。
   - 一人一機：鏡頭同時看到兩個人時，會追蹤比較靠近的那位，並提示「鏡頭前有兩個人，請只留一位玩家」。
   - 用鏡頭玩時，右下角有「鏡頭看到的你」小窗，只畫骨架線條，不顯示影像。

### 六、雲端沒辦法驗證、需要您用平板實測的

1. **衝浪的「蹲低／身體往前彎」**：坐著往前彎時，肩膀下降夠不夠多、能不能觸發加速？請在衝浪裡看左上角的「蹲低加速」條會不會變長。不夠的話先把靈敏度調「高」，或勾「不用蹲低」。
2. **帆船的「舉單手」和「揮手」**：
   - 坐著舉單手時，手要舉過頭才算。學生會不會覺得累、會不會被誤判成雙手？
   - 揮手是否容易觸發？會不會在划手、整理頭髮時誤觸？
3. **「怎麼玩」動畫看不看得懂**：請觀察 2～3 位學生不經講解，能不能看懂小人示範的動作，特別是「鏡像」（舉左手時小人舉畫面左邊的手）。
4. **學校網路**：請在學校平板上打開首頁，按「📶 測試學校網路」。
   - 顯示 ✅ 就代表模型下載得到。
   - 顯示 ❌ 請截圖給我。
5. **平板順暢度**：三款各玩一場，看右下角「格/秒」（25 以上算順）。帆船的畫面最複雜，請特別注意。用鏡頭時最吃力，請在鏡頭模式下看。
6. **兩人同框提示**：請另一位同學走進畫面，看是否出現「請只留一位玩家」，玩家本人是否仍被正確追蹤。
7. **GPU 加速**：雲端只能測「CPU 模式」的姿態辨識；平板上會先試 GPU 加速。若鏡頭小窗的骨架很延遲，請回報平板型號。
8. **難度與時間**：衝浪 90 秒、帆船 2～4 分鐘，以及星星的門檻，是否適合五年級。

### 2. 體感輸入層（`packages/taikan-kit`，獨立資料夾）
- 鏡頭看到的動作 → 變成簡單的「動作事件」：**划槳、左右傾斜、舉手、跳躍、揮臂、蹲低**，另有「看不到人／太近／太遠」的提示。

### 3. 遊戲底座：划舟浮標賽
- 小艇和划槳的人浮在 open-water 的海面上，**跟著浪上下起伏、前後左右搖**；順浪會變快、逆浪會變慢。
- 鏡頭跟在船後面，轉彎時會稍微延遲跟上，看得出船在轉。
- 畫面上有：浮標門數、分數、剩餘時間、速度、指向下一道門的箭頭和距離、目前偵測到的動作、傾斜量、畫面順暢度（格/秒）。
- 遊戲流程：選單 → 3、2、1 倒數 → 比賽 → 結算（星星與分數）→ 再玩一次。**雙手舉高約 1 秒**＝開始／暫停／繼續。用鏡頭時，看不到人會自動暫停。
- 三種難度＝三種天氣：簡單（晴、無風）、普通（微風、側風推船）、挑戰（下雨起霧、浪大、門窄）。雷電一律關閉。
- 動作可跳過：「不划槳也會前進」、「不用傾斜」兩個開關；靈敏度三段。
- **畫質分級**：低（平板）、中、高（電腦）。平板會自動選「低」，並且自動調整解析度維持順暢。
- 遊戲**只接收動作事件**，不直接讀鍵盤。鍵盤模擬、鏡頭、預錄檔對遊戲來說都一樣。

2. **平板效能**：遊戲右下角會顯示「格/秒」。**25 以上算順**；低於 20 請回報平板型號。鏡頭和海面同時跑時最吃力，請在「鏡頭模式」下看。
3. **iPad Safari／Android Chrome 的鏡頭權限**：第一次會跳出詢問；若被拒絕，要到瀏覽器設定裡重新允許。
4. **學校網路**：鏡頭模式需要連到 `cdn.jsdelivr.net` 和 `storage.googleapis.com` 下載模型。若學校網路擋住，鏡頭模式會停在「正在下載姿態模型」，請告訴我，我可以改成把模型放在我們自己的網站。
5. **教室光線**：背光（學生背後是窗戶）、昏暗時辨識會變差。
6. **距離與擺放**：建議 1.5～2.5 公尺、鏡頭約胸口高度，請確認在您的教室可行。
7. **聲音**：選單勾「海浪與風聲」後才會有聲音（瀏覽器規定要先點一下）。平板喇叭音量是否合適。
8. **難度與時間**：學生實際划的節奏、一場 2.5～4 分鐘是否剛好。

### 五、建議下一步

1. 先用 2～3 位學生在測試頁試鏡頭，錄幾段骨架檔回來調門檻。
2. 用學校的平板測順暢度，決定是否要再做「更低」的畫質。
3. 確認划舟好玩後，再開始做第二款「衝浪」（重用約七成程式）。
