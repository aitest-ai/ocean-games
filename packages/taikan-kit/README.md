# taikan-kit（體感工具組）

把「鏡頭看到的人體動作」轉成遊戲聽得懂的**動作事件**。海洋系列體感遊戲在用，之後的「體感野球」也可以直接拿去用（揮臂＝揮棒）。

- **不儲存、不上傳鏡頭影像**：影像只在這台裝置的記憶體裡即時分析，算完就丟；對外只輸出骨架座標（數字）與動作事件。
- **沒有鏡頭也能用**：鍵盤／滑鼠模擬、預錄骨架檔播放，走的都是跟鏡頭一樣的辨識流程。
- **零相依、可抽離**：整個資料夾複製到別的專案就能用，不需要建置工具（瀏覽器原生 ES module）。
- **不依賴外部網站**：姿態模型與執行檔放在本資料夾的 `vendor/mediapipe/`（約 24 MB，裝置第一次只下載其中約 15 MB，之後由瀏覽器快取）。本站載入失敗時才自動改從 CDN 下載。

測試頁：`demo/index.html`（網站上的「輸入層測試頁」）。

## 快速上手

```js
import { createTaikan } from './packages/taikan-kit/src/index.js';

const kit = createTaikan({ sensitivity: 'normal', disabled: ['jump'] });

kit.on('action', (e) => {
  if (e.type === 'paddle') boat.paddle(e.side, e.strength);
});
kit.on('status', (e) => { if (e.tracking === 'lost') game.pause(e.hint); });

await kit.useKeyboard();                 // 鍵盤／滑鼠模擬
// await kit.useCamera({ video });       // 鏡頭（需要使用者同意鏡頭權限、https）
// await kit.useReplay(clip, { loop: true }); // 預錄骨架檔

// 每一格遊戲畫面讀連續值
const steer = kit.state.lean;            // -1（向左）~ +1（向右）
```

## 事件格式

所有事件都是一個簡單的物件，`type` 說明是哪種動作，其他欄位只在需要時出現：

```js
{ type: 'paddle', side: 'left', strength: 0.72, time: 15342, source: 'camera' }
```

| 欄位 | 說明 |
|---|---|
| `type` | 動作種類（見下表） |
| `side` | `left`／`right`／`both`；傾斜時另有 `center`（回正）。一律是**玩家自己的**左右 |
| `dir` | 揮臂的方向：`left`／`right` |
| `strength` | 力道 0.2～1（動作越快越大） |
| `on` | 蹲低：`true` 開始、`false` 結束 |
| `value` | 傾斜當下的數值 -1～1 |
| `time` | 毫秒時間戳（`performance.now()` 的時間軸） |
| `source` | `camera`／`keyboard`／`replay` |

### 動作事件（`kit.on('action', fn)`）

| type | 身體動作 | 欄位 | 冷卻 |
|---|---|---|---|
| `paddle` | 雙手（或同側那隻手）在身體一側由上往下拉；兩手各在兩側同時拉 = `both` | `side`, `strength` | 0.28 秒 |
| `lean` | 上半身向左／右傾（坐著也行）。只在「左／回正／右」改變時送出 | `side`, `value` | 遲滯 |
| `raise` | 手腕舉過頭頂 0.15 秒。單手會多等 0.2 秒確認是不是要舉雙手 | `side` | 0.4 秒，手放下才能再觸發 |
| `jump` | 兩肩快速上升（需站立） | `strength` | 0.7 秒 |
| `swing` | 手腕快速水平揮過（揮棒、甩繩） | `side`（哪隻手）, `dir`, `strength` | 0.45 秒 |
| `crouch` | 兩肩比平常低很多（站姿蹲低；坐姿身體前彎） | `on` | 遲滯 |

### 狀態事件（`kit.on('status', fn)`）

`{ type: 'status', tracking, hint }`，`tracking` 是：

| tracking | 意思 | hint（可直接顯示給學生） |
|---|---|---|
| `ok` | 正常 | （空字串） |
| `lost` | 看不到人（0.4 秒以上） | 看不到你，請站（或坐）到鏡頭正前方 |
| `tooClose` / `tooFar` | 太近／太遠 | 太近了，請往後退一步／太遠了，請往前一點 |
| `edge` | 人在畫面邊緣 | 請移到畫面中間 |
| `hands` | 1.5 秒看不到手 | 請讓雙手也出現在畫面裡 |
| `crowd` | 鏡頭同時看到兩個人超過 1 秒（會追蹤比較靠近鏡頭的那位） | 鏡頭前有兩個人，請只留一位玩家 |

自動校準完成時也會送一次 `{ type: 'status', calibrated: true }`。

### 連續狀態（`kit.state`，每格讀取）

```js
{ tracking: 'ok', hint: '', calibrated: true,
  lean: -0.42, leanSide: 'left',   // 傾斜
  crouch: 0.1, crouching: false,   // 蹲低程度 0~1
  armsUp: 0.5,                     // 0 / 0.5（單手）/ 1（雙手）舉高
  hands: { left: {x, y}, right: {x, y} }, // 以肩膀中點為原點、肩寬為單位
  source: 'camera' }
```

### 設定

- `createTaikan({ sensitivity, disabled })`、`kit.setSensitivity('low'|'normal'|'high')`、`kit.setDisabled(['jump', 'swing'])`
- 被關閉的動作完全不會送出，遊戲要提供替代方式（例如自動前進）。
- `kit.calibrate()`：重新校準（換人、換坐姿時）。開始後只要站好不動約 0.8 秒會自動校準，之後也會慢慢跟著玩家的位置調整。

## 各遊戲怎麼用這些事件

這一輪新增衝浪、帆船兩款，**不需要新的事件種類**，都用既有事件組合出來：

| 遊戲 | 划槳 `paddle` | 傾斜 `lean` | 舉手 `raise` | 揮臂 `swing` | 蹲低 `crouch` | 跳躍 `jump` |
|---|---|---|---|---|---|---|
| 🛶 划舟 | 前進＋轉向 | 轉向（連續值） | 雙手＝開始／暫停 | — | — | — |
| 🏄 衝浪 | — | 轉彎（連續值） | 單手＝花式動作；雙手＝暫停 | — | 加速（用連續值 `state.crouch`，坐姿＝身體前彎） | 預設關閉；開啟時跳過漂流木 |
| ⛵ 帆船 | — | 轉舵（連續值） | 左手＝拉緊帆、右手＝放鬆帆；雙手＝暫停 | 換舷（船頭轉過風的另一邊） | 陣風時壓船（連續值） | — |

每款遊戲用 `kit.setDisabled([...])` 關掉自己不用的動作（例如划舟關掉 `swing`），減少誤判；被玩家「跳過」的動作也一併關掉，遊戲改用自動替代（自動前進、自動調帆、自動閃避……）。

## 畫骨架

`drawSkeleton(ctx, pose, opts)`（`src/draw.js`）：在 2D canvas 上只畫骨架線條。測試頁、遊戲的「怎麼玩」動畫（用模擬人偶示範動作）、遊戲中右下角「鏡頭看到的你」小窗都用它，**不顯示任何鏡頭影像**。

## 鍵盤／滑鼠模擬

| 按鍵 | 動作 | 按鍵 | 動作 |
|---|---|---|---|
| A / D | 左／右划槳 | W | 雙槳 |
| ← / →（按住） | 向左／右傾 | ↓ 或 S（按住） | 蹲低 |
| 空白鍵 | 跳躍 | Q / E（按住） | 舉左手／右手 |
| Enter（按住） | 雙手舉高 | J / L | 右手往左揮／左手往右揮 |

滑鼠與觸控：用 `kit.keyboard.press('paddle-left')`、`press('leanL', true/false)` 綁在畫面按鈕上（測試頁就是這樣做的）。

模擬不是「直接送事件」，而是在操作一個**模擬人偶**（`src/puppet.js`）：按鍵讓人偶做動作，人偶每秒產生 30 格骨架（加上一點抖動），再交給跟鏡頭模式同一個辨識器。所以雲端、自動測試測到的是真正的辨識邏輯。

## 預錄骨架檔

格式 `taikan-pose/1`（JSON，只有數字，沒有影像）：

```json
{ "format": "taikan-pose/1", "name": "paddle-alternate", "keypoints": ["nose", "leftEye", "..."],
  "frames": [[0, 0.5, 0.33, 0.95, "...每個關節點 x, y, 可信度..."], [33, "..."]],
  "expect": { "paddle:left": 4, "paddle:right": 4 } }
```

- 座標是**鏡像**畫面座標（0～1，玩家自己的左手在畫面左邊），跟照鏡子一樣。
- `fixtures/` 裡的 6 個檔案是模擬人偶產生的**合成資料**（`npm run fixtures` 重新產生），不是真人錄的。
- 測試頁「鏡頭」模式有「錄製骨架 10 秒」按鈕，會下載真人的骨架檔（只有座標數字）；放進 `fixtures/` 並填上 `expect`，就成為自動測試的一部分。**建議第一次實測時錄幾段**，用來修正門檻。

## 技術選型與理由

| 決定 | 理由 |
|---|---|
| **MediaPipe Pose Landmarker（lite 模型）**，在瀏覽器裡跑 | 免安裝、免伺服器，影像不離開裝置（符合不上傳的要求）；lite 模型約 5.5 MB，平板 GPU 上每格約 10～30 毫秒；有 33 個關節點與可信度。相較 TensorFlow.js MoveNet，MediaPipe 在 iPad Safari 的支援較完整，且同一套也有手部、臉部模型，野球之後要擴充比較容易。 |
| 版本鎖定 `@mediapipe/tasks-vision@0.10.21`，**檔案放在本站** `vendor/mediapipe/` | 學校網路常擋外部 CDN；放在本站就和網頁同一個來源。本站失敗才改用 CDN（`camera.stats.modelSource` 會顯示 `local` 或 `cdn`）。授權：程式 Apache-2.0、模型依官方模型卡為 Apache-2.0，詳見 `vendor/mediapipe/README.md`。也可以用 `useCamera({ bundleUrl, wasmBase, modelUrl })` 指定其他位置。 |
| GPU 加速，失敗自動改 CPU | 舊平板或某些瀏覽器不支援 GPU 推論時仍可用（會比較慢）。 |
| 鏡頭 640×480、最多每秒 30 格 | 姿態辨識不需要高解析度；降低解析度可以省下 GPU 給海面畫面。 |
| 最多偵測兩個人（`numPoses: 2`），只追蹤最靠近鏡頭的那位 | 規範上一台平板前只站一人；偵測到第二個人時送出 `crowd` 提示，而不是追錯人。 |
| 只用上半身判斷（肩、肘、腕、鼻） | 坐在桌前時腰和腳常被桌子擋住；上半身動作坐著站著都能做。 |

## 延遲與誤判處理

**延遲**

1. **One Euro 濾波器**去抖動：手不動時強力平滑，快速移動時幾乎不延遲（比移動平均好）。
2. **動作做到一半就觸發**：划槳只要手往下拉了約半個肩寬、速度夠快就送出，不等整個動作做完。
3. 模擬人偶的測量（`node --test` 之外手動量過）：一次划槳從「手開始往下拉」到送出事件約 0.18 秒；傾斜約 0.2 秒；跳躍約 0.13 秒；舉手刻意等 0.15～0.35 秒（避免誤觸）。真實鏡頭再加上拍攝與運算約 0.05～0.1 秒。
4. 遊戲畫面和姿態運算在同一台平板上搶 GPU，所以遊戲有「低畫質」並會自動降解析度；需要時可把姿態運算移到 Web Worker（之後的改進項目）。

**誤判**

1. **以肩寬為單位**：所有距離、速度都除以肩寬，離鏡頭遠近、大人小孩都適用。
2. **相對身體判斷**：手的位置是「相對兩肩中點」，所以人整個移動、走近走遠不會被當成划槳。
3. **速度＋位移雙門檻**：要夠快也要夠大，手抖一下不算。
4. **方向要對**：划槳要「垂直為主」，揮臂要「水平為主」，兩者互斥；揮臂後 0.25 秒內不算划槳。
5. **冷卻與重新上膛**：一次划槳只算一次；手要往回舉高一點才能算下一次。
6. **遲滯（hysteresis）**：傾斜超過 0.35 才算傾，回到 0.2 以內才算回正，不會在邊界來回跳。
7. **走動保護**：肩寬在 0.3 秒內變化超過 15%（正在走近／走遠）時，不判斷跳躍與蹲低；跳躍落地 0.7 秒內不算蹲。
8. **自動校準與慢慢跟隨**：記住每個人「平常的姿勢」（肩膀高度、平常就有點歪的肩膀），換坐姿也會慢慢調整。
9. **可信度過濾**：關節點可信度太低的不用；看不到兩肩就不判斷，並送出 `status` 讓遊戲暫停。
10. **靈敏度三段**：所有門檻一起乘上 1.25（低）／1（中）／0.8（高）。

## 尚未在真實鏡頭驗證

門檻值（例如划槳要拉多少、多快）是依人體比例與模擬人偶設定的，**還沒有用真人、真平板調過**。第一次實測請用測試頁觀察：該觸發的有沒有觸發、站著不動或聊天時有沒有亂觸發，必要時先調靈敏度，並錄下骨架檔回報。
