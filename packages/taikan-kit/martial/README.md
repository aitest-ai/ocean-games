# taikan-kit 武術擴充（martial/）

在原本的輸入層上**加掛**武術動作辨識，**不改動**原本 `src/` 裡的任何檔案（海洋系列、體感野球照常使用原本的 kit）。

- 原本的 kit 繼續負責：雙手舉高（開始／暫停）、舉單手（道場用來「跳過這段」）、看不到人、太近／太遠、兩人同框。
- 這個擴充負責：**馬步姿勢**（腳寬、蹲的深度、膝蓋方向、上身挺直）、**出拳**、**提膝（實驗，預設關閉）**。
- 一樣**不儲存、不上傳影像**；只用骨架座標（數字）。

## 用法

```js
import { createMartial, stanceFeedback } from './packages/taikan-kit/martial/index.js';
const m = createMartial({ sensitivity: 'normal', disabled: ['knee'] });
m.on('martial', (e) => { if (e.type === 'punch') bag.hit(e.side, e.strength); });
m.kit.on('action', (e) => { if (e.type === 'raise' && e.side === 'both') game.pause(); });
await m.useKeyboard();               // 或 m.useCamera({ video })
const fb = stanceFeedback(m.state.stance, { target: 0.4, fullBody: m.state.fullBody });
// fb = { key: 'deeper', text: '再蹲低一點', good: false }
```

### 事件（`m.on('martial', fn)`）

| type | 身體動作 | 欄位 | 冷卻 |
|---|---|---|---|
| `punch` | 拳頭從腰間（或下巴前的防守位置）快速往前打到肩膀高度 | `side`（玩家自己的左右）、`strength` 0.2～1 | 0.25 秒；拳頭要收回才能算下一拳 |
| `knee` | 一邊膝蓋抬到接近腰的高度（**實驗，預設關閉**） | `side` | 0.5 秒 |

### 連續狀態（`m.state`）

```js
{ seen, fullBody,            // 有看到人、從髖到腳踝都入鏡
  hint,                      // 例如「請往後退，讓腳也出現在畫面裡（約 2.5～3 公尺）」
  calibrated,                // 已記住「站直」的樣子
  stance: { width,           // 兩腳踝距離 ÷ 肩寬（馬步約 2）
            depth,           // 蹲的深度 0~1（1＝大腿接近水平）
            kneeSpread,      // 膝蓋距離 ÷ 腳踝距離（< 0.72 表示膝蓋往內倒）
            kneesIn, upright, handsAtWaist, torso },
  arms: { left: 'chamber' | 'between' | 'extended', right: ... } }
```

### 口語回饋 `stanceFeedback(stance, opts)`

一次只講最重要的一件事，順序：**安全（膝蓋內夾、蹲太低）→ 入鏡 → 腳寬 → 深度 → 上身**。坐姿版只看「背挺直」和「雙拳收腰」。

## 判斷方式與理由（單一前鏡頭）

| 動作 | 怎麼判斷 | 為什麼這樣做 |
|---|---|---|
| 馬步深度 | 髖部到腳踝的高度，跟「站直時」比少了多少（以肩寬為單位）。少了 36% 算深度 1（大腿接近水平） | 正面看得到「骨盆往下降」，這比算膝蓋角度穩：正面看，膝蓋往前彎時角度會被壓扁，算不準 |
| 腳寬 | 兩腳踝距離 ÷ 肩寬 | 正面最清楚的量，幾乎不受角度影響 |
| 膝蓋內夾 | 蹲下時膝蓋距離明顯比腳踝窄 | 正面看得很清楚，而且是最需要提醒的受傷姿勢 |
| 上身挺直 | 肩到髖的畫面距離沒有比站直時短太多、左右沒有歪 | 往前彎在正面只會讓上身「看起來變短」，**訊號比較弱**，所以只當提醒、不太扣分 |
| 出拳 | 手腕從腰部快速升到肩膀高度，**而且手肘抬到接近肩膀**，維持 0.05 秒 | 正面出拳時手臂朝向鏡頭，畫面上手臂會**變短**，看不出「伸直」。剩下最可靠的線索是「手腕高度」和「手肘抬起」。手肘條件可以排除「把手舉到臉前」；維持 0.05 秒可以排除「雙手舉高經過肩膀」 |
| 提膝 | 膝蓋抬到接近髖部、腳踝比另一腳高很多 | 踢腿的前半段；比整個踢腿穩定很多（見下面的評估） |
| 站直校準 | 雙腳入鏡、站直不動 0.8 秒時自動記住；之後慢慢跟著調整 | 每個人腿長、站的距離都不一樣 |

延遲：出拳從「開始動」到收到事件約 **0.27 秒**（模擬人偶量的；拳頭約 0.14 秒打到底，再加上濾波與 0.05 秒確認）。真鏡頭再多約 0.05～0.1 秒。
遊戲判定時間時已扣回 0.12 秒（`src/dojo/routine.js` 的 `LATENCY`）。

## 模擬人偶（`puppet.js`）

跟原本只有上半身的人偶不同，這個人偶**有腿**，而且用 3D 關節再投影成正面鏡頭的畫面：
出拳是「往鏡頭」伸，畫面上手臂變短，跟真人在鏡頭前的樣子一樣，所以自動測試測到的是單鏡頭真正的難點。
示範動畫用同一個人偶，但從斜前方看（`yaw`），讓學生看得出「拳頭往前打出去」。

鍵盤模擬（道場）：

| 按鍵 | 動作 | 按鍵 | 動作 |
|---|---|---|---|
| F / J | 左拳／右拳 | W | 腳張開／併攏（切換） |
| ↓ 或 S（按住） | 慢慢蹲低 | ↑（按住） | 慢慢站起來 |
| I（按住） | 上身往前傾（測試提醒） | K | 膝蓋內夾（切換，測試提醒） |
| Z / X | 左／右提膝（實驗） | Q / E（按住） | 舉左手／右手（舉單手 1.5 秒＝跳過這段） |
| Enter（按住） | 雙手舉高（開始／暫停） | | |

## 測試

```bash
cd packages/taikan-kit
npm test   # 原本 13 項＋武術 13 項
```

武術的 13 項：自動校準、深度準確度（0.3／0.6／0.9 誤差都在 0.12 內）、回饋順序、蹲太低提醒、
左右交替出拳（每秒 30 格與 15 格）、快速連打、反應時間、馬步沖拳、坐著出拳與坐姿回饋、
不誤判（抖動＋雙手舉高＋蹲下站起，5 組亂數）、提膝開關、跟原本辨識器一起用時舉手仍正常。

## 尚未在真實鏡頭驗證

門檻都是依人體比例與模擬人偶設定的，**還沒有用真人、真平板調過**。特別是：
1. 正面出拳時，真人的手肘有沒有抬到肩膀附近？（有些人出拳手肘很低）
2. 寬鬆褲子、裙子時，膝蓋與腳踝的位置準不準？
3. 平板放得太低或太高時，深度會不會偏？

實測時請用「⏺ 錄製骨架」（輸入層測試頁）錄幾段回來，我可以用來調整。
